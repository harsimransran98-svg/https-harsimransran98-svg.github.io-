How to Port a Chrome Extension to Firefox and Safari

Short answer

You can usually port a Chrome extension to Firefox and Safari without rewriting it: keep one shared codebase, generate a slightly different manifest for each browser at build time, use the promise-based browser.* API (or a polyfill), and wrap the Safari version in a small Xcode app with Apple's converter. The work is mostly in background-script differences, unsupported APIs and each store's review rules.

Start from one shared codebase

Keep popup, options page, content scripts and business logic shared. Put browser differences behind a thin wrapper, and produce one build per browser from the same source. Most extensions end up 90% or more shared.

Firefox

  • Add browser_specific_settings.gecko.id to the manifest — Firefox Add-ons needs a stable extension ID.
  • Firefox runs Manifest V3 background code as an event page ("background": {"scripts": [...]}) rather than a service worker, so generate a Firefox-specific background entry.
  • Firefox supports the promise-based browser.* namespace; Mozilla's webextension-polyfill lets the same code run on Chrome.
  • Submit to addons.mozilla.org; source code may be requested for review if you use a bundler or minifier.

Safari

  • Safari Web Extensions are distributed inside a macOS / iOS app. Apple's xcrun safari-web-extension-converter turns your extension folder into an Xcode project.
  • You need an Apple Developer account, and the app goes through App Store review.
  • Check each API you use against Safari's support — most common ones (storage, tabs, scripting, declarativeNetRequest) work, but some Chrome-only APIs do not.
  • Test on both macOS Safari and iOS Safari if you ship to iPhone and iPad.

Edge and other Chromium browsers

Edge, Brave, Opera and Arc run Chrome extensions directly. Edge has its own Add-ons store, which accepts the Chrome build with minor listing changes.

A build setup that scales

Use one build step that outputs dist/chrome, dist/firefox and dist/safari, each with its own manifest. Run the same automated checks on all three so a fix in shared code reaches every browser at once.

Questions

Do I need to rewrite my extension for Safari?

Usually not. The converter wraps your existing web extension in an app; the work is adapting unsupported APIs and testing on Safari.

Can one person maintain extensions for three browsers?

Yes, if the code is shared and each browser build comes from the same source — maintenance then means one change, three builds.

Which store is hardest to get approved?

Each has different rules: Chrome focuses on permissions and data use, Firefox may review source code, and Apple reviews the whole app. Clear permission justifications help with all three.
